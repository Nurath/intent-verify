2. Scope caveat on criteria 1, 4, 7 (I judge them PASS, but only at the limiter's interface). The module (8 lines, source captured with cat -n) is just a gate allow_login(ip) -> bool. It has no credential check, no username parameter, no notion of endpoints; _a is mutated only inside allow_login. So 'valid credentials log in / invalid fail' (c1), 'different usernames' (c4) and 'other endpoints' (c7) were exercised through verifier-written shims (login(): limiter first, then a toy credential check; handle(): only /login consults the limiter) plus structural facts (signature (ip); a second positional arg raises TypeError; only one public callable). These three verdicts hold by the module's API shape: the limiter cannot count by username or by non-login traffic. They do not prove that a real login handler calls it only on the login route; that wiring is outside this module.
3. Negative controls (same 21 checks against deliberately wrong limiters, all flagged): limit 6 -> 17 mismatches; window 30s -> 5; window 120s -> 5; one global counter ignoring IP -> 7; blocked attempts also recorded -> 3. 4. Outside the request (not counted as failures):
   a) Not thread-safe (no lock around check+append). With sys.setswitchinterval(1e-6) and 32 simultaneous threads on one IP, 166 of 300 trials let more than 5 through (worst 20 allowed in one trial). With the default 5 ms switch interval: 0 of 300 trials (32 threads) and 0 of 1000 trials (8 threads) exceeded 5. So the race is real but hard to hit at default settings; a threading.Lock around the check-and-append would close it.
   b) Uses wall-clock time.time(): in the suite, after a 1h backward clock step, an IP with 5 recent attempts was still blocked 61s of real time later (info line: 'wall clock stepped back 1h; 5 allowed [True, True, True, True, True] -> attempt 61s later by real elapsed time: False'). time.monotonic() would avoid this.
   c) No eviction: the dict keeps one key per IP ever seen (20 keys still held after every window had expired), so memory grows with the number of distinct IPs.
